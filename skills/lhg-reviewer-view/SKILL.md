# lhg-reviewer-view：评审打分视角自查

> ## 声明（必读）
>
> **评审偏好因资助机构而异**：本 skill 使用通用权重与通用评审逻辑，
> 各机构（国自然/科技部/省基金/企业）的实际权重、函评/会评流程、
> 限项规则均以当年通知为准。**本 skill 不能预测真实评审结果**，
> 内容仅供参考。

> 目标：站在评审人视角，用打分表给自己的申请书"挑刺"，P0 问题清零再提交。
> 核心纪律：**模拟≠真实；苛刻≠为难；每条意见都要有定位**。

## 1. 何时使用

- 申请书初稿完成，准备提交 → 全流程自查
- 跑 `/lhg-grant:review-sim` 做评审模拟 → 本 skill 是打分依据
- 被批"立项依据不够"但不知道缺什么 → 直接第 3 步

## 2. 输入与输出

**输入**：申请书目录（六件套齐全）。

**输出**：四维打分表 + 一票否决项排查 + P0/P1/P2 修改清单。

## 3. 四维打分表（通用权重，百分制）

| 维度 | 权重 | 满分项长什么样 | 常见扣分点 |
|---|---|---|---|
| A 立项依据 | 30 | 科学问题一句话说清，三层论证完整，文献新且准 | 问题是伪问题/已解决；文献综述式堆砌；需求层空喊口号 |
| B 研究内容与方案 | 30 | 内容聚焦（3~4 个），技术路线箭头连贯，预算对齐 | 内容发散；路线图是装饰；内容和钱对不上 |
| C 创新点 | 20 | 2~3 条实质创新，每条有证据/论证 | 形容词创新；"首次"无检索支撑；包装旧工作 |
| D 研究基础与条件 | 20 | 前期成果→本项目的逻辑链，团队条件具体 | 基础与内容脱节；"实力雄厚"式空话；条件不具备 |

**打分纪律**：每个维度先写扣分理由，再给分。不许先给高分再找理由。

## 4. 评审人三问（每节必过）

1. **So what？** —— 这事做成了，科学上/应用上有什么不一样？
   答不上来 = 立项依据没立住。
2. **Why you？** —— 为什么是你做，而不是别人做？
   答不上来 = 研究基础没讲清。
3. **Why now？** —— 为什么现在做，时机是什么？
   答不上来 = 前沿跟踪没做够。

## 5. 一票否决项（出现即"不予资助"，不看总分）

1. 科学问题不成立（伪问题、已解决的问题、工程问题包装成科学问题）。
2. 研究基础与申请内容脱节（做 A 的基础，申请 B 的项目）。
3. 预算严重错配或虚高（出现"餐饮费"类科目，或总额虚高）。
4. 创新点全部是包装（评审都是同行，糊弄不过去）。
5. 诚信问题：冒用成果、重复申报未声明、代表作造假。
6. 限项违规：超项申请（以当年通知为准）。

## 6. 模拟评审输出模板

```markdown
## 模拟评审打分

| 维度 | 得分/权重 | 扣分理由 |
|---|---|---|
| A 立项依据 | 22/30 | 科学问题表述分散在三处，未加粗标出（-4）；近3年文献仅2篇（-4） |
| B 研究内容与方案 | 24/30 | 技术路线图箭头②解释不清（-3）；研究内容三无对应预算（-3） |
| C 创新点 | 14/20 | 第2条"首次"无检索支撑（-4）；第3条是集成，无"1+1>2"论证（-2） |
| D 研究基础与条件 | 16/20 | 团队缺关键方向成员（-4） |
| **总分** | **76/100** | 参考线：85+ 优先资助，70~85 可资助，70 以下危险 |

## 一票否决排查：通过 / 未通过（列出项）

## 修改清单
- P0（不改大概率被毙）：……
- P1（建议改，能提分）：……
- P2（打磨）：……
```

**参考线是经验值，不是承诺**：76 分在有的机构能中，在有的机构陪跑。
分数线每年浮动，本表只用于定位短板。

## 7. 分节评审挑刺清单（逐节自查）

### 摘要（评审只花 1 分钟，先看这里）

- [ ] 科学问题一句话能找到吗（还是藏在第三段）？
- [ ] 有量化预期吗（还是"重要意义"四个字）？
- [ ] 关键词 3~5 个，是"能被检索到"的词吗？

### 立项依据（评审花 5 分钟，决定第一印象）

- [ ] 第一段能说清"为什么重要"吗（还是直接堆文献）？
- [ ] 科学问题加粗/标出了吗？评审找三遍找不到 = 扣分。
- [ ] 每条"现有局限"后面跟引用了吗？无引用的批评 = 空口。
- [ ] 近 3 年文献占比 ≥30% 吗？全是 5 年前的文献 = 前沿跟踪不够。

### 研究内容（评审看逻辑）

- [ ] 3~4 个，不过多（发散）/过少（工作量不够）？
- [ ] 每个内容都有"对应预算"吗？
- [ ] 预期成果可考核吗（论文/专利/原型/数据集，不是"深入研究"）？

### 创新点（评审看诚意）

- [ ] 独立成节了吗？还是散在正文里让评审自己找？
- [ ] 每条都有证据/论证吗？"首次"有检索支撑吗？
- [ ] 删掉形容词还剩什么？如果只剩形容词，重写。

### 技术路线（评审看可行）

- [ ] 箭头连得上吗？每个箭头能一句话解释吗？
- [ ] 关键技术标★了吗？最难的部分藏起来了还是亮出来了？

### 可行性（评审看靠谱）

- [ ] 前期成果→本项目的逻辑链画出来了吗？
- [ ] 风险预案 2~3 条，有备选方案吗？还是只有表决心？

### 预算表（评审会算账）

- [ ] 科目全在白名单吗？每行有测算依据吗？
- [ ] 总额/比例超限了吗？设备费占比畸高吗？
- [ ] 每笔钱都能找到对应的研究内容吗？

## 8. 反模式（不许这么干）

- **自查走过场**：打分全是 28/30、29/30——那你不需要自查，需要诚实。
- **意见没有定位**："立项依据不够充分"——充分在哪不够？第几段？怎么改？
- **P0 问题留到"以后再说"**：P0 不清零就提交 = 浪费一次申报机会
  （很多机构一年只有一次）。
- **把模拟分当真**："模拟 88 分，稳了"——模拟只能找短板，不能预测结果。
- **通篇只挑格式**：格式是底线，科学问题才是评审真正打分的地方。

## 8. 自检与反馈

**质检门**：

- [ ] 四个维度都写了扣分理由吗（先理由后给分）？
- [ ] 一票否决 6 项逐项排查了吗？
- [ ] 评审人三问每节都过了吗？
- [ ] 每条意见都定位到章节/段落了吗？
- [ ] P0 清单为空吗（不为空就不提交）？
- [ ] 报告里写了"模拟不能预测真实结果"吗？

**标准冒烟用例**：用插件 `fixtures/grant-bad` 跑一遍四维打分，
确认总分 <70 且 P0 清单非空；用 `fixtures/grant-good` 跑，
确认总分 ≥85 且 P0 清单为空。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-reviewer-view]`），
描述：资助机构、哪个维度权重拿不准。
