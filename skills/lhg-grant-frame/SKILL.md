# lhg-grant-frame：申请书框架（立项依据→可行性）

> ## 声明（必读）
>
> 1. **评审偏好因资助机构而异**：国自然、科技部重点研发、省基金的评审侧重点
>    各不相同。本 skill 给的是**通用底线框架**，具体指南、限项、格式要求
>    **以当年申报通知为准**，内容仅供参考。
> 2. **诚信红线**：研究基础、代表作、预算必须真实。虚构前期成果、夸大预算、
>    冒用他人成果——碰都别碰，一票否决且影响学术声誉。

> 目标：把研究想法变成"评审愿意给钱"的申请书框架。
> 核心纪律：**科学问题先行，创新点独立成节，内容与预算对齐**。

## 1. 何时使用

- 有了研究想法，准备写申请书 → 全流程
- 立项依据被批"逻辑散/像文献综述" → 直接第 3 步
- 创新点写不出来/写出来像包装 → 直接第 5 步
- 技术路线图不会画 → 直接第 6 步
- 可行性分析只会写"我们很牛" → 直接第 7 步

## 2. 输入与输出

**输入**：研究主题一句话 + 目标资助类型（探索型/任务型）+ 代表作清单。

**输出**：申请书六件套框架（摘要/立项依据/研究内容/创新点/技术路线/可行性），
每节一句话核心 + 写作要点。

**先定类型**：探索型（青年/面上）重科学问题与创新，任务型（重点研发）
重目标分解与考核指标。类型定错，后面全错。

## 3. 立项依据：三层论证

立项依据不是文献综述，是"为什么值得给钱"的论证链，三层缺一不可：

### 3.1 第一层：需求（为什么重要）

- 国家需求：卡脖子、重大工程、战略方向（引用政策文件，不许空喊口号）。
- 学科前沿：国际研究趋势（引用近 3 年顶刊/顶会，证明你跟踪前沿）。

### 3.2 第二层：科学问题（为什么难）

- 从需求凝练出 1~2 个**科学问题**（不是技术问题，不是工程问题）。
- 现有研究为什么解决不了：逐条指出局限，每条跟引用。
- **纪律**：写不出科学问题 = 选题没想透，回炉，不许用"应用前景广阔"代替。

### 3.3 第三层：研究基础（为什么是你）

- 前期工作如何自然导向本项目（代表作→本项目的逻辑链）。
- 已具备的条件：数据、平台、团队（具体，不许"条件优越"四个字打发）。

### 3.4 立项依据写作模板（4 段）

1. 领域重要性（需求层，3~5 句）。
2. 研究现状与局限（逐条，每条跟引用，不许堆砌）。
3. 拟解决的科学问题（1~2 个，加粗/标出，让评审一眼看到）。
4. 本项目思路与前期基础（自然过渡到研究内容）。

## 4. 研究内容：写法

设 3~4 个研究内容（太多=不聚焦，太少=工作量不够），每个固定格式：

```
研究内容一：XXX（标题即结论倾向）
- 做什么：……
- 怎么做：关键方法/技术（呼应技术路线）
- 得到什么：预期成果（可考核：论文/专利/原型/数据集）
- 对应预算：XXX 费 XX 万元
```

**"对应预算"这行是本 skill 的硬性要求**：写研究内容时就想好花多少钱，
评审看"内容和钱对不上"是最常见的扣分点。

## 5. 创新点：四象限（独立成节）

创新点必须**独立成节**（04-innovation.md），不许散在正文里让评审自己找。
归入四类（至少占一类，写 2~3 条）：

1. **学术思想创新**：新理论/新模型/新科学发现（最难，最值钱）。
2. **技术方法创新**：新方法/新工艺，且有可论证的优势。
3. **应用创新**：新场景/新系统，带来实质性突破（单纯"首次应用"多数不认）。
4. **集成创新**：多技术集成产生"1+1>2"（需论证为什么集成是难的）。

**每条创新点格式**：一句话陈述 + 一句话证据/论证。
禁用"首次""填补空白"除非有文献检索支撑（见 lhg-paper-plan 同款纪律）。

## 6. 技术路线：文字版流程图

```
科学问题 → 研究内容一 → 关键技术 A → 预期成果 1 ↘
         → 研究内容二 → 关键技术 B → 预期成果 2 → 总体目标
         → 研究内容三 → 关键技术 C → 预期成果 3 ↗
```

要求：

- 每个箭头可解释：为什么这一步能导向下一步（评审会顺着箭头挑逻辑断裂）。
- 标出**关键技术/难点**（评审最关注的部分，用★标出）。
- 画不出路线图 = 研究内容之间没逻辑关系，回炉重想。

## 7. 可行性分析：三件套

1. **理论可行**：科学原理上走得通（引用/预研数据支撑）。
2. **技术可行**：关键技术已有预研/前期成果（列代表作对应关系）。
3. **条件可行**：数据、平台、团队、合作（具体到名字和数字）。

**必须有风险预案**：列出 2~3 个主要风险 + 备选方案。
不写风险预案 = 告诉评审"我没想过失败"，可信度打折。

## 8. 摘要：最后写（50 字立项 + 全文浓缩）

1. 科学问题一句。
2. 研究思路一句。
3. 关键内容一句（3 个研究内容压缩）。
4. 预期突破一句（量化，不许"重要意义"）。
5. 关键词 3~5 个。

## 9. 反模式（不许这么干）

- **立项依据写成文献综述**："张三做了A，李四做了B"堆 3 页，科学问题藏在角落。
- **创新点靠形容词**："开创性""突破性"堆满，证据只有"我们很有信心"。
- **研究内容与预算脱节**：内容写 500 万的活，预算报 50 万（或反过来）。
- **技术路线画成 ornament**：箭头连不起来，评审一眼看出是后贴上去的。
- **可行性只会表决心**："我们团队实力雄厚"——评审要的是证据，不是决心。
- **一稿多投/重复申报不声明**：红线，各机构都有查重与声明要求。

## 10. 自检与反馈

**质检门**：

- [ ] 科学问题能用一句话说清吗（加粗标出了吗）？
- [ ] 立项依据三层（需求/科学问题/基础）齐了吗？
- [ ] 每个研究内容都有"对应预算"行吗？
- [ ] 创新点独立成节，每条有证据/论证吗？
- [ ] 技术路线每个箭头能解释吗？关键技术标★了吗？
- [ ] 风险预案写了 2~3 条吗？
- [ ] 当年申报通知的限项/格式要求核对过了吗？

**标准冒烟用例**：找一份已获批的本领域申请书（公开的），
用第 3~7 步反推它的框架，看能否还原出"科学问题→内容→创新→路线"链条。
还原度 80% 以上算过关。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-grant-frame]`），
描述：资助类型、卡在哪一步、AI 给的哪句话拿不准。
